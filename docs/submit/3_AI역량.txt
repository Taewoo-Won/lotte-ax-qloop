■ 한 줄 요약
사람이 매번 지시를 넣지 않아도 스스로 검증하고 고치며 도는 AI 에이전트 루프를 직접 설계·운영해 왔습니다. 클라우드 서버(Ubuntu)에 Claude Code(헤드리스)와 OpenAI Codex CLI를 함께 두고 cron·systemd로 묶어 돌립니다.

■ 주요 프로젝트
1) 자율 연구 루프(2026.09~10): 시장 데이터에서 반복 가능한 규칙을 찾는 연구를 에이전트에게 맡기고, 사람 개입 없이 159라운드를 돌렸습니다. 매 라운드 프롬프트 앞에 불변 규칙, 폐기된 가설 목록(부활 조건 필수), 남은 산출물 목록을 붙여 기억에 의존하지 않게 했습니다. 감사·실행·제안·탐색 네 모드로 나누어 새 방향 탐색만 사람 승인을 받게 했고, 사전등록과 홀드아웃 분리를 지켰습니다. 결론은 "검증된 규칙 0건"이었고, 시스템이 스스로 그렇게 판정했습니다. 그럴듯한 결과를 지어내지 않는 루프를 만드는 법을 여기서 배웠고, 이것이 Q-Loop의 '근거 2회 전에는 안 바꾼다' 규칙의 출발점입니다.
2) 일감 자동 수주 엔진(2026.08): 프리랜서 플랫폼 일감 탐지 → 자동화 가능 판정 → 산출물 선제작 → 쓰기 권한 없는 별도 채점 에이전트의 검수 → 입찰 → 결과 추적 → 규칙 자기 정제까지 잇는 파이프라인입니다. 정제기는 불변 영역과 바꿀 수 있는 영역을 나누고, 같은 근거가 3번 반복돼야 규칙을 바꾸며, 회차당 2개만 바꾸고, 모든 변경을 원장과 스냅샷으로 되돌릴 수 있게 했습니다. 첫 실전 입찰에서 10명 중 9위를 한 뒤, "입찰자는 발주자에게 먼저 연락할 수 없다"는 구조적 원인을 찾아 전략을 바꿨습니다.
3) 사고 구조 복원 엔진(2026.09): 공개 SNS 글을 수집해 '무엇을 보고, 어떤 사건에 반응하고, 무엇을 따지고, 어떤 가설을 세우고, 무엇으로 확인하는가'라는 의사결정 필드로 구조화했습니다. 비정형 서술을 결정에 쓰는 필드로 코딩한다는 점에서 이번 과제의 개방형 응답 코딩과 같은 문제입니다. 학습·검증 데이터를 물리적으로 분리해 검증 데이터를 한 모델이 아예 못 읽게 했습니다.
4) 공공데이터 공모전 응모 파이프라인(2026.10~): 공식 통계 API 수집기(키를 로그·출력에서 가림), HWP/HWPX 문서 생성과 렌더링 검수, 블라인드 AI 심사와 원출처 대조를 묶어 여러 대회 응모작을 만들었습니다.

■ 이번 응모작을 만든 방식
같은 방식으로 만들었습니다. 제가 목표와 검증 원칙(실측 숫자만, 비교 전 사전등록, 정답 모듈 격리)을 정하고, AI 에이전트가 과제 분석·구현·실험·문안 초안을 맡았으며, 제가 검토해 제출합니다.

■ 기술 스택
Python(numpy·pandas·scikit-learn), Claude Code, OpenAI Codex CLI, OpenAI Agents SDK·Responses API(이번 프로토타입), systemd·cron, SQLite, GitHub Actions, Java/Spring Boot(백엔드 학습 중).

■ 일하는 원칙(실패에서 나온 것)
측정과 판정을 분리한다. 불확실한 응답을 성공으로 읽지 않는다. 모든 상수에 도출 근거를 남기고, 없으면 지운다. 문서에 적힌 안전장치가 코드에 실제로 있는지 확인한다. 합계가 맞아도 구간별로 다시 맞춘다.
