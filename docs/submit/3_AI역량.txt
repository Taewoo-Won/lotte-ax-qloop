■ 한 줄 요약
매 단계 명령을 붙여넣지 않아도 에이전트가 스스로 검증하고 고치며 도는 루프를 설계·운영해 왔습니다. 클라우드 서버(Ubuntu)에 Claude Code(헤드리스)와 OpenAI Codex CLI를 함께 두고 cron·systemd로 묶어 돌려 왔습니다.

■ 주요 프로젝트
1) 자율 연구 루프(2026.09~10): 시장 데이터에서 반복 가능한 매매 규칙을 찾는 연구를 에이전트에게 맡겨 159라운드를 돌렸습니다. 매 라운드 프롬프트 앞에 불변 규칙, 폐기된 가설 목록(부활 조건 필수), 남은 산출물 목록을 붙여 모델의 기억에 기대지 않게 했습니다. 감사·실행·제안·탐색 네 모드로 나눠 새 방향 탐색만 제가 승인했고, 사전등록과 홀드아웃 분리를 지켰습니다. 사전등록 검증을 통과한 규칙이 1건 나왔지만 기대 수익이 목표에 못 미쳐 채택하지 않았고, 최종 결산에서 제가 정한 목표 기준을 통과한 규칙은 0건이었습니다. 결과를 부풀리지 않고 그대로 보고하게 만든 경험이 Q-Loop의 '근거가 2회 쌓이기 전에는 바꾸지 않는다' 규칙으로 이어졌습니다.
2) 일감 자동 수주 엔진(2026.08): 프리랜서 플랫폼 일감 탐지 → 자동화 가능 판정 → 산출물 선제작 → 쓰기 권한 없는 별도 채점 에이전트의 검수 → 입찰 → 결과 추적 → 규칙 자기 정제까지 잇는 파이프라인입니다. 정제기는 불변 영역과 바꿀 수 있는 영역을 나누고, 같은 근거가 3번 반복돼야 규칙을 바꾸며, 회차당 2개만 바꾸고, 모든 변경을 원장과 스냅샷으로 되돌릴 수 있게 했습니다. 첫 실전 입찰에서 10명 중 9위를 한 뒤, "입찰자는 발주자에게 먼저 연락할 수 없다"는 구조적 원인을 찾아 전략을 바꿨습니다.
3) 사고 구조 복원 엔진(2026.09): 공개 SNS 글을 수집해 '무엇을 보고, 어떤 사건에 반응하고, 무엇을 따지고, 어떤 가설을 세우고, 무엇으로 확인하는가'라는 의사결정 필드로 구조화했습니다. 비정형 서술을 결정에 쓰는 필드로 바꾼다는 점에서 이번 과제의 개방형 응답 분류와 같은 문제입니다. 학습·검증 데이터를 물리적으로 분리해 검증 데이터를 한 모델이 아예 못 읽게 했습니다.
4) 공공데이터 공모전 응모 파이프라인(2026.10~): 공식 통계 API 수집기(키를 로그·출력에서 가림), HWP/HWPX 문서 생성과 렌더링 검수, 블라인드 AI 심사와 원출처 대조를 묶어 여러 대회 응모작을 만들었습니다.

■ 이번 응모작을 만든 방식
같은 방식으로 만들었습니다. 제가 목표와 검증 원칙(실측 숫자만, 비교 실행 전 설계 고정, 정답 모듈 격리)을 정하고, AI 에이전트(Claude)가 과제 분석·구현·실험·문안 초안을 맡았으며, 별도 심사 에이전트의 블라인드 채점을 반영했습니다. 서버에 연결해 둔 OpenAI Codex CLI로 실제 모델 출력을 받아, 검증기가 맞는 문장을 막던 결함을 찾아 고쳤습니다. 마지막으로 제가 검토해 제출합니다.

■ 기술 스택
Python(numpy·pandas·scikit-learn), Claude Code, OpenAI Codex CLI, OpenAI Agents SDK·Responses API(이번 프로토타입), systemd·cron, SQLite, Java/Spring Boot(백엔드 학습 중).

■ 실패에서 배운 것
가장 비싼 실수는 에이전트의 보고를 그대로 믿은 것이었습니다. 문서에는 있던 일일 작업 상한이 코드에는 없어 같은 작업이 반나절 반복된 적이 있고, 합계만 맞고 구간별로는 두 오류가 상쇄된 결과를 통과시킨 적도 있습니다. 그 뒤로 숫자는 직접 다시 계산하고, 판정은 만든 쪽과 다른 에이전트에게 맡깁니다.
