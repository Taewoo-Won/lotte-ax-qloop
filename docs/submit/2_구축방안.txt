■ 구성: LLM은 해석과 문장, 코드는 숫자와 판단, 사람은 승인
- OpenAI Agents SDK 0.24.0 + Responses API(Structured Outputs)로 만듭니다. Agent Builder는 2026-11-30 종료 예정이라 쓰지 않고, 호스티드 Evals도 종료 예정이라 평가는 자체 하네스로 돌립니다.
- 에이전트 도구: 회차 숫자표 조회, 문항 은행 변경안(폐기·승격·새 문항과 근거), 다음 설문 초안, 설문 발송, 액션플랜 배포. 설문 발송과 플랜 배포는 needs_approval로 담당자 승인 없이는 실행되지 않습니다.
- 출력 가드레일: 플랜 문장은 숫자마다 인용 키를 달아야 하고, 검증기가 표에서 다시 계산해 하나라도 틀리면 배포를 막습니다.

- 흐름: [누적 자료]→문항 은행→설문 구성→(승인)→발송·취합→개방형 코딩→분석·배정→액션플랜(검증)→(승인)→실행→ERP 매출→진화→다음 설문. 주기는 분기 1회, 진화 판단은 근거가 2회 쌓일 때만.
- 담당자 화면: 세그먼트별 이번 분기 추천 액션과 대상 거래처, 각 추천의 근거 문항과 효과 크기, 다음 설문에서 바뀌는 문항과 그 이유(원장). 영업사원은 거래처별 방문 리스트를, 마케팅은 캠페인 타깃 리스트를 받습니다.

■ 모델 배분(오류가 다음 단계로 번지는지, 되돌릴 수 있는지로 정함)
- 개방형 응답 1차 코딩(대량·되돌릴 수 있음): gpt-6-luna. 사람이 코딩한 200건과 일치도(κ)를 재서, 선행연구의 zero-shot 수준(κ 0.76)에 못 미치면 판정 모델로 올립니다.
- 코딩 불일치 판정·새 문항 문구·플랜 문장(고객에게 나가거나 경영 판단에 쓰임): gpt-6.1-sol.
- 누적 자료 중 스캔본·표 이미지: gpt-6.1-terra.
- 결정 기여도·효과 추정·배정·폐기/승격: 결정론 코드(LLM 미사용). 합성 응답자는 의사결정에 쓰지 않습니다. 실리콘 샘플링이 응답을 동질화한다는 연구 결과 때문입니다.

■ 데이터 파이프라인
- 입력 어댑터 3종: 누적 설문(hwp·pdf·xlsx·csv)→문항 은행, 응답(구글폼·네이버폼·엑셀)→표준 응답표, ERP 고객별 분기 매출→결과표. 형식이 바뀌어도 어댑터만 고치고 뒤 단계는 그대로 둡니다.
- 고객 식별자는 가명 처리 후 결합하고, 개인정보는 LLM에 보내지 않습니다.

■ 통계 설계
- 회귀식: 매출 변화율 = 액션 주효과 + 문항 + 액션×문항 상호작용(릿지). 문항의 결정 기여도 = 상호작용 계수의 최대 |t|.
- 무작위 대조군 15%(불변 하한 10%). 배정이 관측된 응답에만 의존하므로 응답을 통제한 회귀에서 효과로 읽힙니다.
- 진화 규칙: 기여도 |t|<1.0이 2회 연속이면 폐기, 새 문항은 |t|≥2.0이 2회 연속이면 승격, 회차당 폐기·추가 각 2개, 응답 상관 0.7 이상 중복 정리, 폐기 4분기 뒤 재시험, 대조군 기준 이득이 2표준오차 넘게 떨어지면 직전 변경을 되돌림.
- 불변 영역(진화기가 못 건드림): 추세용 앵커 문항, 대조군 하한, 검증기, 가명 처리.
- 알려진 약점과 보완: ①고객이 적은 B2B 세그먼트는 신호 문항 오폐기가 약 30% → 세그먼트 간 정보를 빌리는 계층 모델로 교체 ②액션 여러 개 중 최대 |t|를 쓰므로 우연히 큰 값이 나올 수 있음 → 순열로 만든 귀무분포로 임계값 보정.

■ 검증 현황(저장소 lotte-ax-qloop, 실측)
- 시뮬레이션 비교(시드 20, 사전등록), 실제 응답 13만 건 가지치기, 검증기 시험: 맞는 문장 390/390 통과, 숫자·부호·자릿수·근거 문항·끼워 넣은 숫자로 틀리게 바꾼 문장 1,528/1,528 차단. 이 시험은 문장 생성기와 검증기를 같은 사람이 만든 기계적 보증이므로, 본선에서 OpenAI 모델이 쓴 문장으로 다시 잽니다.
- 에이전트 코드는 시뮬레이션의 정답 모듈을 import하지 못하게 시험으로 막았습니다.

■ 본선 1박 2일 계획(현장 데이터·구체화된 과제 당일 공개 전제)
- 0~2시간: 데이터 구조 파악, 어댑터 3종 매핑. 매출이 없으면 재구매·문의 같은 대리 결과로 바꿉니다.
- 2~6시간: 누적 자료를 문항 은행으로 적재, 첫 회차 분석.
- 6~12시간: 액션플랜·검증기·승인 흐름 연결.
- 12~18시간: 현장 과거 회차를 순서대로 다시 돌리는 백테스트로 진화 규칙의 효과를 현장 데이터에서 측정.
- 18~24시간: 담당자 화면과 발표. 측정한 숫자만 씁니다.
- 사전 작성 코드 사용 가능 여부는 미확인입니다. 허용되면 저장소를 그대로 쓰고, 불허면 설계·규칙·시험 케이스만 가져가 핵심부(분석·진화·검증 약 560줄)를 다시 구현합니다.

■ 성과 지표
설문 문항 수, 응답률, 대조군 대비 액션 순이익, 개방형 코딩 κ, 검증기 차단율, 되돌리기 횟수.
